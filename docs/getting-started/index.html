01 · Before you start

Install once. Start two services.

This is a developer-run application, not a desktop installer. If Studio already opens, skip to page 3. The locally verified platform is Windows.

Install Git, 64-bit Python 3.14.6, Node.js 24.18.0 and npm, matching this repository's baseline. Download or clone the project, then open PowerShell in its root folder.

Prepare the checkout

py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m pip check
cd frontend
npm.cmd ci
npm.cmd run build
cd ..

Terminal 1 — backend, from the project root

.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000

Terminal 2 — interface, from the project root

cd frontend
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
Open http://127.0.0.1:5173 in your browser. Keep both terminals open. Use Stop Graph before shutting them down with Ctrl+C.

Webots is optional for your first run. Install a compatible Webots R2025 release to use Webots physics and external worlds. The built-in simulator needs no Webots installation.

Do not add unrestricted backend --reload when using Webots: generated controller files can trigger a backend restart. Detailed installation reference: README.md and docs/BASELINE.md.

02 · Choose your starting point

Create a project through Robot setup.

On a fresh session, click Robot setup. If a project is already open, stop it and save it first. Applying a new simulation can replace the current graph.

Supported custom simulation: four-wheel differential drive, two equal-radius wheels per side, with fixed level lidar and camera frames. A CAD assembly alone does not define a working robot. Other drive types and arbitrary actuated mechanisms are not covered by this workflow.
03 · Bring your own CAD model

Turn geometry into robot links.

  1. Open Model Builder, then Import STEP or Import OBJ. Check dimensions against a known measurement. STEP imports use millimetres before conversion to metres.
  2. Group rigid parts into links. Keep the chassis fixed; give each wheel a separate moving joint. Imported CAD placements begin as fixed joints.
  3. Set the base at ground level with +X forward, +Z up. Put wheel centres one radius above ground. Wheel axes must point along base +Y.
  4. Add fixed sensor frames for the lidar and camera. Set the correct offsets and level orientations. Confirm the scale/orientation checkbox.
  5. Save an editable model for future changes. Click Use in robot setup, or Export URDF bundle and import that ZIP in Robot setup.
The direct handoff carries meshes, smooth normals and builder-assigned colors. No manual mesh copying is needed.

CAD textures/material finishes and measured dynamics are not imported. Simplify dense models: embedded assets are limited to 20,000 triangles and 6 MiB of compact asset JSON; builder ZIP upload is limited to 8 MiB. See docs/MODEL_TO_SIMULATION.md.

04 · Tell Studio how the robot moves

Check all four wheel assignments.

  1. Select the correct Robot base frame.
  2. Assign distinct left-front, left-rear, right-front and right-rear wheel joints. Left/right are relative to the robot facing +X.
  3. For mesh wheels, enter the measured Wheel radius override (m). The included mesh rover uses 0.12 m; your robot may differ.
  4. Set Robot clearance radius to enclose the body and wheels. Planning clearance must be at least as large.

Webots physics

Expand this section to enter body mass, mass per wheel, motor limits, damping, friction and slip. Body mass excludes the wheels.

Check before continuing

Equal wheel radii. Four distinct joints. Correct pivots. All other joints fixed. Do not reduce clearance merely to bypass a validation error.

Physics settings are approximate and apply to Webots, not the built-in geometric simulator. They are not measured automatically from CAD.

05 · Sensors and project creation

Check setup, then apply.

In Sensors, choose the fixed lidar and camera mounting frames. Use the camera mount frame, not an optical frame with different axes. For the sample: lidar_link and camera_link.

06 · Optional: choose a Webots environment

Select a world before driving.

  1. Stop the graph and open World setup. Choose an installed world or enter an external .wbt path on the backend computer.
  2. Set spawn X/Y, heading in radians, and base height. Choose open, level floor with enough room for the whole robot.
  3. Review mapping bounds and resolution. Bounds limit the map; they do not supply an obstacle map or guarantee that floor exists there.
  4. Click Check world. Read the compatibility results and inspect the placement preview in Webots.
An installed-world listing is not a compatibility guarantee. Supported imports use R2025 ENU (Z-up) worlds. Studio replaces existing top-level robots; review the removal list. Unsupported structures produce an explanation.

World setup can also be used before Robot setup. In that case, return here after configuring the robot to check its physical placement. Changing worlds resets saved maps, home positions and missions.

07 · Check physical placement

Four supported wheels. A clear body.

  1. Keep the preview simulation running so the robot can settle. Preview motors stay disabled.
  2. If placement is invalid, move to clear floor in Webots or correct the numeric spawn fields. You can also try Find nearby safe position.
  3. Inspect a suggested position. When available, click Use Webots position to adopt the observed pose.
  4. Click Check world again. Wait for Robot placement: valid, acknowledge the map/mission reset, then Apply world.
The nearby search checks up to 25 positions at the entered height. It can be cancelled. It does not search every room or find another floor automatically.

A compatible world structure is only the first check. Physical support, body/wheel contact, settling and sensor readiness must also pass. Startup repeats these checks. A valid spawn does not qualify all terrain or prove a complete navigation route.

08 · First motion

Drive a little. Check what you see.

  1. Click Start Graph. Wait for sensor data and the measured map; Webots may take time to launch.
  2. Select Manual. Click the Keyboard driving pad so it has focus.
  3. Hold W briefly, then release. Check that the visible robot moves forward and stops.
  4. Try a small turn. Check that the visual robot, estimated pose and measured walls behave consistently.
  5. Use Stop to keep sensors running while stopping motion. Use Stop Graph to end the runtime.

W A S D

W / ↑ forward
S / ↓ reverse
A / ← and D / → turn
Space: zero velocity

If walls drift badly or the visual robot disagrees with its estimated pose, stop and check wheel assignment, radius, scale, sensor frames and slip before trying autonomy.

What the map means

Black cells are occupied; gray cells are unknown; light cells are measured free space. Mapping starts from sensor observations, not from a perfect copy of the Webots world.

09 · Explore, navigate and return

Start with one short mission.

1 · Set home

The first map pose becomes home by default. At a suitable known position, Set home here saves a new home and pauses navigation.

2 · Try a waypoint

On the SLAM waypoints map, click a nearby clear destination, then Run waypoints. Draft clicks alone do not start motion.

3 · Explore

Explore map selects reachable frontiers. It returns after the configured target limit or when no eligible frontiers remain.

4 · Return

Return home requests a route back and alignment to the home heading. Home reached means stopped at the estimated home; it is not docking.

Keep the mission under control

Control / statusMeaning
Pause motion / Resume motionPause or resume the current autonomous mission.
Cancel missionStop that mission. Choose a new mission to move again.
no_path / obstacle_stopWait stopped while fresh map data and replanning may clear the blockage.
navigation_failed / stalledInspect the robot and route. Clear the cause, then use Retry navigation or choose a new goal.
sensor_timeoutMotion is stopped while waiting for fresh mapping data.

Choose algorithms after the first successful run

In Settings, the available planners are A* and Dijkstra; controllers are proportional and fuzzy logic. Begin with the defaults. Changing algorithms does not fix a wrong wheel radius, unsupported placement or drifting localization.

Exploration can stop before a whole building is mapped. Global localization, loop closure and arbitrary-world reliability are not established. Test your own environment in small stages.
10 · Save, reopen and get unstuck

Keep a project you can reproduce.

  1. Use Save project to download the applied robot, graph and settings.
  2. To keep a measured map, open Maps, enter a name and click Capture map, then save the project again.
  3. Later, use Open project to restore the saved JSON. Confirm the starting pose when using a saved map.
  4. Keep the editable builder model too. Keep external Webots worlds and referenced assets at accessible paths.
